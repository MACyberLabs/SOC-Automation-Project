# Wazuh Ubuntu

This section documents the configuration of the Wazuh server and the Windows 10 client reporting to Wazuh.

The Wazuh configuration was completed after the TheHive server was configured.

![Wazuh](https://github.com/MohamedAbdallaProjects/SOC-Automation-Project/blob/main/Images/image%20(10).png?raw=true)

## Wazuh Configuration

To begin configuring Wazuh, the Wazuh Dashboard was accessed using the administrative credentials obtained during the previous setup.

Initially, the dashboard showed that no agents had been added to the Wazuh manager.

### Recovering Wazuh Credentials

If the Wazuh credentials were not available, the Wazuh installation files could be checked.

The Wazuh installation files were located on the Wazuh server and the files were listed.

The installation files were extracted using:

    tar -xvf wazuh-install-files.tar

After extracting the files, the Wazuh installation directory was entered and the contents were listed.

The password file was:

    wazuh-passwords.txt

The password file was displayed using:

    cat wazuh-passwords.txt

The admin password was used to log into the Wazuh Dashboard.

The Wazuh API user was also identified for later use in the lab to perform response capabilities.

### Adding the Windows 10 Agent

From the Wazuh Dashboard, Add agent was selected.

The operating system was set to:

    Windows

For the server address, the public IP address of the Wazuh server was entered.

An agent name was assigned:

    mydfir

The existing group selection was left as the default.

Wazuh then generated an installation command for the Windows agent.

### Installing the Wazuh Agent

On the Windows 10 machine, a PowerShell window was opened with Administrator privileges.

The installation command generated by the Wazuh Dashboard was copied and pasted into PowerShell.

The command was then executed to install the Wazuh agent.

After the installation was completed, the Wazuh service was started using:

    net start WazuhSvc

The service could also be checked through Windows Services.

The Wazuh Service was checked to confirm that it was running.

![Wazuh](https://github.com/MohamedAbdallaProjects/SOC-Automation-Project/blob/main/Images/image%20(11).png?raw=true)

### Verifying the Wazuh Agent

After starting the Wazuh service, the Wazuh Dashboard was checked again.

Initially, the Windows agent appeared as disconnected.

After waiting for a few seconds, the agent became active.

The Wazuh Dashboard then showed:

    Total agents: 1
    Active agents: 1

This confirmed that the Windows 10 machine was successfully checking in to Wazuh.

The Security Events section could then be opened to query events.

![Wazuh](https://github.com/MohamedAbdallaProjects/SOC-Automation-Project/blob/main/Images/Image%20(4).png?raw=true)

## Result

The Wazuh server was successfully configured and the Windows 10 client was successfully added as a Wazuh agent.

The Windows 10 machine was reporting to the Wazuh server and the agent was shown as active in the Wazuh Dashboard.

The environment was now ready for the next stage, where telemetry would be generated and an alert related to Mimikatz usage would be created.
